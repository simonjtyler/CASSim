# CASSim: agent instructions

## Development workflow: local checks, batched CI (agreed 2026-11-20; review 1 December 2026)

GitHub Actions minutes are limited, so the thorough testing happens locally and CI runs once per batch.
- **Feature work:** a branch in its own worktree, small local commits, the focused tests from `docs/testing/TESTING.md` while working.
- **Before a branch merges into local `main`:** `uv run python -m tools.local_ci` must pass. It runs exactly CI's checks: Ruff, Ty, pytest with coverage, the coverage floors, the traceability check, and CI's browser list. Add `--full-e2e` for shell, startup, PWA, worker or publishing changes. A pass on a clean tree is recorded against the commit's tree. Merge with `git merge --no-ff`, then rerun `local_ci` on `main`, then delete the branch and worktree.
- **One `local_ci` run at a time, machine-wide:** only one agent or worktree may run `tools.local_ci` at once, with or without `--full-e2e`. Two runs side by side compete for the CPU and make the time-based tests fail for reasons that have nothing to do with the code. The tool enforces this with a lock in the user's own folder (`%LOCALAPPDATA%\CASSim\local_ci.lock`), shared by every worktree and clone: a second run prints `local_ci: waiting for the run in <path> ... to finish` and starts when the first ends. Let it wait; do not kill a run you did not start, and do not delete the lock file to get past it (a run that dies releases the lock by itself). Before the browser tests, a run also waits until 4 GB of memory is free (up to 30 minutes, then it starts anyway), since a browser suite started on a short machine was stopped part way. Focused pytest runs while working are fine, but keep them short while another agent's `local_ci` is going. `--status` and the pre-push check do not wait.
- **Batches:** about once or twice a week, or when a milestone slice is done, push local `main` as a `batch/<yyyy-mm-dd>` branch and open **one** PR. Open it as a draft, because drafts run no CI. Review the batch in Claude Code with `/code-review` on the batch branch (the diff from `origin/main`; there is no review workflow on GitHub since 2026-11-27). Fix the findings that hold up on local branches, merge them, and rerun `local_ci` on `main` before pushing again. Then mark the PR ready: CI runs once. Merge with `gh pr merge --merge`. Do not push or open PRs between batches unless Simon asks.
- **Hooks:** `uv run pre-commit install` installs the commit hook (Ruff, Ty) and a pre-push hook that refuses commits whose tree has not passed `local_ci`. Never bypass it (`--no-verify`, `CASSIM_SKIP_LOCAL_CI`) unless Simon asks.
- **What CI does:** it runs on ready PRs and manual dispatch only, not on pushes to `main`. A batch that touches only docs, the corpus, non-browser tests or the UI-free engine packages skips the browser job. The testing site deploys on a push to `main` that changes the app; the help pages deploy when `docs/wiki` changes.

## Project
A static, installable (PWA) multi-app browser shell for calculator and programming devices. The current all-in-one build contains Nspire, Pseudocode & Python and Scientific devices; ClassPad and Prime are later plug-ins. Device engines run client-side via Pyodide where needed; the UI is Flet. Owner: Simon Tyler, a VCE maths teacher (Methods, Specialist), strong in maths and physics, writes Python. ## Decisions already made (do not re-litigate)
- Repo lives at `C:\dev\CASSim`, outside OneDrive. The virtualenv is the in-project `.venv` (uv default; do not set `UV_PROJECT_ENVIRONMENT`). Commit and push to a Git remote often.
- Correctness is judged by **symbolic/numeric equality**, not TI's exact output text. Maths is rendered from LaTeX.
- Python and pseudocode run sandboxed, by CASSim's own interpreter (a Python program is translated to pseudocode first, and so is a Console line), so Run runs at once with no prompt; nothing opened, imported or linked runs until Run (decision 0040, 2026-11-27). Never execute user code with Python's `exec` or `eval`.
- **CASSim's own interface follows SDD-15** (`docs/design/SDD-15-shared-interface.md`, agreed 2026-11-26): the CASSim and Doc menus have the same sections in the same order in every app, built with `cassim.app.cassim_menu` and `cassim.app.saved`; one shared theme and Appearance dialog (`cassim.app.appearance`); sentence case everywhere; Material dialog buttons (Cancel, then the confirming action last); ✓ for panels and ● for views, with fixed labels; unavailable items greyed, not hidden; Computer, Tablet and Handheld views, all usable by touch. Device-copied menus keep the device's order and numbering. Before adding a CASSim-own feature, check SDD-15 section 11, and update section 10 when a gap is closed. `tests/test_interface_rules.py` fails on a label not in sentence case, a dialog with Cancel last, or a new literal colour; fix the code rather than adding to its frozen lists.
- Geometry page is out of initial scope.
- Python 3.14 (matches Pyodide 314.0.7). Tooling: **uv, Ruff, Ty, Git, pytest, Hypothesis, Playwright**.
- Core engine (`src/cassim/core`) is pure Python and must never import Flet. SymPy is touched only inside `core/compat/sympy_adapter.py`. Core is fully typed and passes Ty strict.
- TI syntax is parsed with a real tokenizer + Pratt parser, not regexes (see `spikes/ti_eval_spike.py` for why).
- Canonical text is Unicode: `e` is a variable, `ⅇ` is Euler's constant, `ᴇ` is the exponent marker. ASCII is only a REPL spelling (`to_ascii` in `core/format.py`).
  - **Do not overwrite or "normalise" these symbol conventions** (reviewed and confirmed 2026-11-01; see `docs/decisions/0007-parser-grammar.md` and `to_ascii`). Canonical Unicode forms: `ⅇ` Euler's constant, `ⅈ` imaginary unit, `ᴇ` exponent marker (`3.14ᴇ6`), `π`, `∞`, `ᵀ` (U+1D40), `ʳ`, `ᵍ` (U+1D4D, a lowercase superscript g, ASCII `@g`; not the uppercase `ᴳ`), `°`, `∠`, `▶`. Plain `e`, `i`, `E` are ordinary variables, so `2e3` is `2*e3`. Typed (input) spellings in corpus `in:` lines are TI's ASCII ones: `@e`, `@i`, `@E`, `@t`, `@r`, `@g`, `@d`, `@<`, `@>`, `pi`, `infinity`; `out:` lines use the Unicode forms. Never replace `ⅇ`/`ᴇ` with `e`/`E` in outputs, and never replace `@>` with `▶` in inputs.
- Statistics must follow the TI/school convention, not numpy: quartiles are the median of the lower and upper halves (median excluded when n is odd), e.g. Q1 of {1,4,9,16,25,36,49,64} is 6.5 and Q3 is 42.5 (numpy's default gives 7.75 and 39.25). Implement it directly; do not call `numpy.percentile`/`quantile`. Sample sd uses n-1 (`sx`), population uses n (`σx`).
- Data pages and graphs (decision 0031, 2026-11-13): within a Problem the engine's variables are the only copy of the data and every page is a view of them; the document stores definitions and view state, not values. Each page's model and cached scene are kept, and a switch rebuilds the controls from them without waiting for the engine (keeping hidden Flet controls alive is slower: spike A). Pages can split into two panes. SciPy and NumPy are not shipped (statistics are pure Python and mpmath; SciPy only checks them in tests). The General Maths categorical charts (dot chart, bar chart, pie chart) are Must.
- Other simulator behaviours to match (details in `docs/testing/TESTING.md` section 14): Approximate mode shows decimals inside symbolic results (`3.·x^2`); Float n shows n decimal places below 1 (`0.02666667` in Float 8) and switches to `ᴇ` notation below 10^-n (`9.ᴇ-4` in Float 3; Fix 2 gives `5.00ᴇ-3`); a typed space between numbers is a product, even in `[ ]`; `round(x)` keeps 12 places; `1/0` and `ln(0)` give `undef`, not errors; undefined variables echo unchanged; `int(-2.5)` = -3 (floor); `sinh⁻¹(1)` stays unevaluated in Auto mode; spreadsheet whole-column references are `a[]`; Graphs coordinates label to three significant figures (decision 0034) and Integral accepts typed bounds.
- Pseudocode (M7b, reviewed 2026-11-06; see `docs/decisions/0020` and `0021`): Euler's `e` is on by default; run limits are 1,000 passes per loop, 20,000 trace steps and recursion depth 100; `[ ]` always makes a list and only `( )` groups; `ax` is not split into a*x in the default and strict syntax presets (it is in the vcaa and author presets). The syntax file (`runtime/pseudocode/syntax.py`) drives the lexer and parser.
- IP boundary and clean room (`docs/decisions/0028`, NFR-LEG-008, NFR-LEG-009): copy behaviour, structure and vocabulary (names, syntax, menus and numbering, key positions, settings), never expression or code (artwork, fonts, help or Reference Guide prose, ROM, data tables). Learn behaviour only by using TI's software; never decompile or inspect its binaries. Paraphrase `references/`, never paste it into `src/`. Short functional labels may match the device.
- **Open and Save, Import and Export (every app; decision 0033, FR-DOC-010):** Open, Save and Save As work on documents kept by name in storage the app looks after (IndexedDB in the browser, the app's own preferences on the desktop), never a file dialog. Files on disk are Import and Export only: `.cassim.json` for a calculator document, `.py` and `.pseudo.txt` for code, CSV and XLSX for sheet data, and `.tns` there too if it is ever built (FR-DOC-006). The Nspire, Pseudocode & Python and Scientific apps follow this, and so must every later device; `cassim.app.saved.SavedDocuments` gives a device the Open, Save and Save As dialogs.
- Library UDFs (`mm_`, `sm_`, `gm_`) are `.tns` and not loadable. Port them to native Python later (M5). LazyMath is Unlicense, so porting is permitted; record the check in `docs/decisions/` first.
- Sites, bundles and publishing (2026-11-13; PLAN.md sections 14 and 15, README "Publishing"):
  - `cassim-app` (stable) and `cassim-calc` (testing) are the all-in-one Home shell with every built device. The current built choices are Nspire, Pseudocode & Python and Scientific (`cassim-sci`); single-device bundles get their own stable-only sites (`cassim-tin`, `cassim-pseudo`, `cassim-cp`, `cassim-prime`) as they are released. `cassim-wiki` is the help site and lists the sites.
  - Each device is a plug-in package (`devices/nspire`, `classpad`, `pseudocode`, `prime`: long ids in code, short names for bundles and sites) that never imports another device; device UIs are separate from the shell. Pseudocode (the Code view) is a device with its own site (Q23 revised).
  - A batch merge to `main` deploys testing (when the app changed) and the help pages (when `docs/wiki` changed); a GitHub release deploys stable. Never deploy stable by hand with wrangler unless Simon asks.
- Decisions from the SRS review (2026-11-02; see `docs/SRS.md`):
  - CASSim is a simulator, not a hardware emulation. "Close enough not to confuse a student or teacher" is the bar; exact text only where a case says `compare: exact`. Released under the MIT licence (decision 0042, 2026-11-28).
  - No telemetry or analytics of any kind; no server; share links carry the document in the URL fragment (keep under about 2,000 characters, else export a file). Imported documents and share links never auto-run Python or programs.
  - Computer and Handheld modes are equal top priority; Tablet/demo is Should. Dark is the default theme; themes come from a user-editable config file with a fallback to Dark.
  - Primary test targets are Chromebooks, Chrome and Safari; Edge and Firefox are smoke-tested. Hosting is any free static host.
  - `.tns` import/export is Won't for now. The Python page moved from M5 to M7 (Should) with the pseudocode pages; pages are self-contained in M7 (the `py()` call and `cassim` variable bridge, FR-PY-001 and FR-RUN-011, are a later Could-have: the real Nspire does not allow it); the sandbox is mandatory, and there is no trust prompt (decision 0040). Exam-restriction mode is Could.
  - No fixed performance or size budgets: cold start and download size are measured and reported. Cancel must take effect within 1 s.
  - Accessibility is Should: gaps go in `docs/accessibility.md` and are stubbed, not skipped.
  - Coverage target 90% on `core/`, 80% on `device`, `doc`, `sheet`, `stats`, `graph`. Every SRS requirement ID must appear in a test or be listed as untested with a reason (`docs/traceability.md`, generated by `tools/`).

## Conventions
- Small commits, conventional commit messages. Every behaviour change ships with a test; cite the SRS requirement ID in the test where one applies. Design docs go in `docs/design/` (SDD set listed in SRS appendix A). Fix lint and type errors rather than suppressing them.
- **No inline Python edits through a Bash heredoc** (`python - <<'EOF'`) when the text has backslashes: LaTeX such as `\boldsymbol`, Windows paths such as `C:\dev`, or regexes. Python reads them as string escapes, so `\b` becomes a backspace (ruff PLE2510) and `\d` makes the search text fail to match. Use a direct file-editing tool for exact changes. For scripted edits, write a `.py` file to the scratchpad with raw strings (`r"..."`), pass it the target path, and open files with `newline=""` so Windows does not write CRLF. Heredocs are fine for text with no backslashes (commit messages, PR bodies).
- Known failing corpus cases are `xfail(strict=True)` with a reason.
- Branch protection (GitHub ruleset `protect-main`; see the 2026-11-09 chat). Never push to `main` directly: check `git worktree list`, work on a branch in its own worktree, merge it into local `main` after `local_ci` passes, and reach GitHub only through a batch PR (see "Development workflow"). Merge with `--no-ff` locally and `gh pr merge --merge` on GitHub (merge commits are kept on purpose; linear history is **not** required, so do not rebase or squash unless asked). Force pushes to `main` and deleting `main` are blocked. The required check is `check` (it needs the `python` job and, when it runs, the `browser` job), and it must be green before a batch merges; if it fails, fix the cause and push again rather than bypassing. Required approvals are 0. The admin bypass is Simon's escape hatch: never use it, and never edit or delete the ruleset, without being asked. Delete the branch and worktree after merge.
- Never put directory junctions or symlinks in a worktree, including links to the evidence repository or to ignored folders. Point tools at the original location instead (`CASSIM_EVIDENCE`). Before removing a worktree, check for links; removing a worktree can delete the contents of linked directories.
- Keep the docs and code in step. When you add, move or remove a package under `src/cassim/`, update the architecture map in `PLAN.md` section 3 in the same commit (`tests/test_architecture.py` checks it, and the `[placeholder]` tags). When you touch code listed in the PLAN.md section 12 follow-up table and its trigger is met, do that cleanup then and delete the row.
- Never use TI logos, artwork or ROM content. The product name is CASSim.
- Evidence is kept in the separate `CASSim-evidence` repository, cloned beside the working copy (`C:\dev\CASSim-evidence`; decision 0039, `tools/evidence.py`): simulator screenshots (`corpus/shots/`, `docs/testing/*-shots/`), capture briefs, run plans, `simulator-todo.md` and `references/`, at the same relative paths as here. Never commit them to this repository (`.gitignore` refuses them) and never include them in the build. `docs/testing/app-shots/` shows CASSim itself and stays here.
- Reference material is in `references/` in the evidence repository (Reference Guide, shortcuts, VCE teacher resource books, LazyMath UDF guides and libraries). Do not edit it.
